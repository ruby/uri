# URI

[![CI](https://github.com/ruby/uri/actions/workflows/test.yml/badge.svg)](https://github.com/ruby/uri/actions/workflows/test.yml)
[![Yard Docs](https://img.shields.io/badge/docs-exist-blue.svg)](https://ruby.github.io/uri/)

URI is a module providing classes to handle Uniform Resource Identifiers [RFC3986](http://tools.ietf.org/html/rfc3986).

## Features

* Uniform way of handling URIs.
* Flexibility to introduce custom URI schemes.
* Flexibility to have an alternate URI::Parser (or just different patterns and regexp's).

## Installation

Add this line to your application's Gemfile:

```ruby
gem 'uri'
```

And then execute:

    $ bundle

Or install it yourself as:

    $ gem install uri

## Usage

```ruby
require 'uri'

uri = URI("http://foo.com/posts?id=30&limit=5#time=1305298413")
#=> #<URI::HTTP http://foo.com/posts?id=30&limit=5#time=1305298413>

uri.scheme    #=> "http"
uri.host      #=> "foo.com"
uri.path      #=> "/posts"
uri.query     #=> "id=30&limit=5"
uri.fragment  #=> "time=1305298413"

uri.to_s      #=> "http://foo.com/posts?id=30&limit=5#time=1305298413"
```

### WHATWG URL Standard

The default parser follows RFC 3986. `URI::WHATWG_PARSER` parses URLs as web browsers do, following the [WHATWG URL Standard](https://url.spec.whatwg.org/), including domain to ASCII (IDNA, [UTS #46](https://www.unicode.org/reports/tr46/)) for non-ASCII domains. IDNA uses the Unicode data of the running Ruby, so a domain with a character added in a later version of Unicode than `RbConfig::CONFIG["UNICODE_VERSION"]`, or than that of the data bundled for IDNA (18.0.0), is invalid:

```ruby
URI::WHATWG_PARSER.parse("HTTP://EXAMPLE.com:80/a/../b c")
#=> #<URI::HTTP http://example.com/b%20c>
URI::WHATWG_PARSER.parse("http://0x7f.1/")
#=> #<URI::HTTP http://127.0.0.1/>
URI::WHATWG_PARSER.parse("http://日本語.jp/").host
#=> "xn--wgv71a119e.jp"

# A relative reference is resolved against a base URL.
URI::WHATWG_PARSER.join("http://example.com/a/b", "../c")
#=> #<URI::HTTP http://example.com/c>
```

It can also replace the default parser for the whole process:

```ruby
URI.parser = URI::WHATWG_PARSER
URI("http://ＥＸＡＭＰＬＥ.com/")
#=> #<URI::HTTP http://example.com/>
URI.parser = URI::RFC3986_PARSER
```

Only http, https, ws, wss and file URLs become instances of their scheme's class. Other schemes, ftp, mailto and ldap among them, become `URI::Generic`, since `URI::FTP`, `URI::MailTo` and `URI::LDAP` interpret their components by their own RFCs. With `URI.parser = URI::WHATWG_PARSER`, code that relies on those classes no longer works for such URLs: for example, `URI.open("ftp://...")` of open-uri, which opens a `URI::FTP` only, tries to open a local file instead and raises `Errno::ENOENT`.

The setters of a URI built by `URI::WHATWG_PARSER` follow the setters of the URL Standard. A value that the URL Standard ignores raises `URI::InvalidComponentError`:

```ruby
uri = URI::WHATWG_PARSER.parse("http://example.com/")
uri.host = "日本語.jp"
uri.port = "8080abc"
uri.to_s  #=> "http://xn--wgv71a119e.jp:8080/"
uri.port = "abc"
# raises URI::InvalidComponentError
```

As for any URI, `scheme=` does not change the class of the object. Parse the URI again to get the class of its new scheme, before handing it to code that checks the class, such as open-uri, which uses TLS for a `URI::HTTPS` only:

```ruby
uri = URI::WHATWG_PARSER.parse("http://example.com/")
uri.scheme = "https"
uri                                 #=> #<URI::HTTP https://example.com/>
URI::WHATWG_PARSER.parse(uri.to_s)  #=> #<URI::HTTPS https://example.com/>
```

## Development

After checking out the repo, run `bin/setup` to install dependencies. Then, run `rake test` to run the tests. You can also run `bin/console` for an interactive prompt that will allow you to experiment.

`rake test:wpt` runs the conformance tests of `URI::WHATWG_PARSER`: web-platform-tests' `urltestdata.json`, `toascii.json` and `setters_tests.json`, and Unicode's `IdnaTestV2.txt` and `NormalizationTest.txt` (the latter for the Unicode version of the running Ruby; the cases of the former that succeed with a character unknown to it are not run). It fetches them over the network, unless `WPT_URLTESTDATA`, `WPT_TOASCII`, `WPT_SETTERS`, `IDNA_TEST_V2` and `NORMALIZATION_TEST` name local files. The cases that are known to fail are listed in `test/wpt/urltestdata_exclusions.json` and `test/wpt/setters_tests_exclusions.json`; regenerate them with `rake test:wpt:update_exclusions`.

The Unicode data that IDNA needs and Ruby has not, the Bidi_Class and Joining_Type values in `lib/uri/whatwg_parser/idna_data.rb`, is generated by `rake idna:generate`. Set `UNICODE_VERSION` (for example `UNICODE_VERSION=18.0.0`) to generate it for another version of Unicode.

To install this gem onto your local machine, run `bundle exec rake install`. To release a new version, update the version number in `version.rb`, and then run `bundle exec rake release`, which will create a git tag for the version, push git commits and tags, and push the `.gem` file to [rubygems.org](https://rubygems.org).
